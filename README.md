# 정찬민의 홈페이지 · 알고리즘 오락실

기술개발연구프로젝트(2026-2) 개인 홈페이지 과제입니다.

## 1. 목적

**전략 의뢰소.** 구현해 보고 싶은 매매 전략을 메일로 받아, 규칙을 숫자로 함께 정리하고, 코드로 만들어 실제 과거 데이터로 백테스트한 뒤 결과 페이지로 공개합니다. 잘 안 된 결과도 그대로 공개합니다. 지금까지 직접 만든 전략·검증 6개가 “이렇게 결과를 받게 된다”는 예시(결과물)이고, 예측 게임 2개는 따로 “게임” 페이지에 있습니다.

- 무료, 연구·교육 목적. 과거 데이터 백테스트·모의 기록만 다룹니다.
- 하지 않는 것: 돈을 받는 일, 특정 종목 추천·매매 신호 발송, 실제 계좌·거래소 자동매매 연결, 수익 보장. (유료로 신호를 계속 보내면 유사투자자문업 문제가 될 수 있어 선을 긋습니다.)
- 의뢰자의 연락처는 공개하지 않습니다. 의뢰 현황에는 동의한 경우 전략 이름과 닉네임만 올립니다.

**지금까지 만든 6개에서 본 것**: 다음 날 방향을 미리 맞히는 규칙은 거의 찾지 못했습니다(4번 효과 없음, 7번 방향 0~1칸). 대신 언제 크게 움직이는지(7번), 어떻게 하면 덜 잃는지(2번 200일선 필터)는 보였습니다.

## 전략 의뢰 받기 (`requests/`)

1. 메일로 의뢰가 오면 규칙을 되물어 숫자로 정합니다(메일 양식은 첫 화면 “의뢰하기”).
2. `requests/requests.csv`에 한 줄 적습니다: `접수일, 전략, 의뢰자(닉네임만), 상태(접수/진행 중/완료/보류), 결과(machines/이름.html), 공개(Y/N), 메모`. 메모와 공개=N 줄은 사이트에 나가지 않습니다.
3. 구현·백테스트가 끝나면 `machines/이름.html` 결과 페이지를 만들고(아래 “새 결과 페이지 추가하는 법”) 상태를 완료로, 결과 칸에 주소를 적습니다.
4. 이메일·전화번호 같은 연락처가 의뢰자 칸에 들어가면 `requests/build.py`가 멈춥니다(테스트로 검사).

```bash
python3 requests/build.py
python3 -m unittest discover -s requests -p 'test_*.py' -v
```

## 오늘의 한 판 (게임 페이지)

방문자가 들어와서 바로 해 볼 수 있는 판입니다. 매일 한국 시간 오전 9시(바이낸스 일봉 마감)에 회차가 열리고, **내일 오전 9시 비트코인 종가**가 크게 오름 / 횡보 / 크게 내림 중 어디일지 맞힙니다. ‘크게’ = 최근 20일 하루 변동 폭 × 0.5(6번과 같은 방식, 하루 단위). 기준은 `arena/config.json`에 결과를 보기 전에 고정했습니다.

- 선수: 방문자 각자 · 방문자 군중(다수결) · 기계(5번 BREAKOUT·2번 REBOUND 엔진을 그대로, 1번 데모 논조 점수) · 기준선(늘 횡보, 동전 원숭이). 기계의 선택은 방문자가 고른 **뒤에** 보여 줍니다.
- 연습 경기: 기계들이 같은 문제를 2017년부터 매일 풀었다면 — 늘 횡보 49.3%, REBOUND 48.8%, BREAKOUT 47.7%, 1번 데모 규칙 42.2%, 동전 원숭이 34.5%. **늘 횡보가 보스**입니다.
- 투표는 구글 폼 → 시트(5주차 방식) → Actions가 집계합니다. 방문자가 쓴 값이라 믿지 않습니다: 투표 시간 밖·없는 선택지·형식이 틀린 행은 건너뛰고(배포는 멈추지 않음), 한 브라우저당 회차마다 첫 표만 셉니다. 공개 파일에는 방문자 번호를 넣지 않습니다.
- 닉네임 순위: 12자 이내, 한글·영문·숫자·공백·`_.-`만, 링크 불가. 결과가 나온 회차 3번 이상. 시트에 `숨김` 열을 만들고 `Y`를 적으면 그 방문자의 이름을 숨깁니다.
- 폼 연결 전에는 예측이 방문자 브라우저에만 저장됩니다(화면에 그렇게 표시).

```bash
python3 arena/build.py                      # ARENA_CSV_URL이 있으면 투표도 집계
python3 -m unittest discover -s arena -p 'test_*.py' -v
```

#### 투표 폼 연결하기
1. 구글 폼 새로 만들기 → 질문 4개, 모두 **단답형**, 제목을 정확히: `회차`, `예측`, `닉네임`, `방문자` (닉네임만 선택 응답).
2. 설정 → 응답: 로그인 요구·응답 1회 제한·조직 사용자 제한을 **모두 끔**(학교 계정이면 “한국외국어대학교 사용자로 제한”을 꺼야 함).
3. 응답 → 스프레드시트에 연결 → 그 시트에서 파일 → 공유 → 웹에 게시 → 응답 시트 · CSV → 주소를 저장소 Variables `ARENA_CSV_URL`에 넣기.
4. 폼 오른쪽 위 ⋮ → 미리 채워진 링크 받기 → 네 칸에 아무 값이나 넣고 링크 복사 → 그 링크를 알려 주면 `arena/config.json`의 `form`(formResponse 주소와 `entry.숫자` 4개)을 채웁니다.
5. 부적절한 닉네임은 응답 시트 맨 오른쪽에 `숨김` 열을 만들어 `Y`.

### 1번 TRADING FLOOR
AI 에이전트 13명이 분석·토론·심사해 판정을 내는 기계입니다. 실제 기계는 로컬에서만 돌고, 코드와 프롬프트는 공개하지 않습니다. 결과: 공개 판정 24건 중 24시간 뒤 대조한 코인 19건은 맞음 2 · 빗나감 12 · 움직임 작음 5(마지막 판정 2026-09-01).

- **브라우저 데모** (`assets/floor-demo.js`): 원본 `server/demo.js`의 지표·대사·순서를 옮겼습니다. AI를 부르지 않고 코인 실시간 시세로 5단계를 연출 재생합니다. 판정에 의미가 없습니다. 매수·매도·관망 방향에 맞춰 손절·목표 위치를 바꿉니다.
- **플레이 기록** (`records/`): 기계가 낸 실제 판정을 적은 목록입니다. 코인 기록은 판정 24시간 뒤 바이낸스 현물 가격으로 등락을 계산해 원본 `report.js`의 `judge()`와 같은 규칙(±1% 미만은 “움직임 작음”)으로 판정합니다.

```bash
python3 records/build.py                       # 시트 또는 records/records.csv → data/records.json
python3 records/build.py --previous <배포된 records.json 주소>   # 시트 접속 실패 시 배포된 기록 유지
python3 -m unittest discover -s records -p 'test_*.py' -v
```

#### 플레이 기록 시트 연결 (5주차 방식)

| 열 | 필수 | 내용 |
|---|---|---|
| 일시 | 필수 | `2026-08-24 22:06` (한국 시각) |
| 모드 | 필수 | 알고리즘 / 스캘핑 / 공격 |
| 종목 | 필수 | BTC, SOL, 삼성전자 … |
| 판정 | 필수 | 알고리즘: 매수·매도·관망 / 스캘핑: 롱·숏·패스 / 공격: 롱·숏 |
| 확신도 | 필수 | 0~100 정수 |
| 판정가 | 필수 | 0보다 큰 숫자 |
| 통화 | 필수 | USD / KRW |
| 메모 | 선택 | 한 줄 |
| 공개 | 필수 | Y인 행만 웹에 표시 |

1. 새 스프레드시트 → 파일 → 가져오기 → `records/records.csv`
2. 파일 → 공유 → 웹에 게시 → 시트1 · 쉼표로 구분된 값(.csv) → 게시 (주소가 `output=csv`로 끝나야 함)
3. 저장소 Settings → Secrets and variables → Actions → **Variables** → `SHEET_CSV_URL` = 게시 주소
4. Actions → Site → Run workflow (예약 실행은 몇 시간씩 밀릴 수 있음)
5. 잘못된 행이 있으면 build가 행 번호와 이유를 출력하고 멈춥니다. 이전 화면이 그대로 남습니다.

## 자동화

`.github/workflows/site.yml` — Pages Source는 **GitHub Actions**입니다.

| 작업 | 하는 일 |
|---|---|
| test | 9개 폴더의 파이썬 테스트(118개), 화면 스크립트 문법 검사. 실패하면 배포하지 않음 |
| build | 플레이 기록(시트 검사), 김프 기록 1건 추가, 오늘의 한 판(투표 집계), 6번 상황 통계, 7번 시간대 지도·2·5번 백테스트(하루 한 번), 공개 파일만 `_site`로 모음 |
| deploy | GitHub Pages에 게시 |

| 실행 조건 | 언제 |
|---|---|
| push | main에 Push할 때 |
| schedule | `cron: "7 * * * *"` — 매시 7분 예약. 실제로는 몇 시간씩 밀리거나 빠짐(첫날 18시간에 3번) |
| workflow_dispatch | Actions 화면의 Run workflow (시트를 고친 뒤) |

- 배포하지 않는 경우: 테스트 실패, 시트 데이터 잘못, 배포된 김프 기록을 읽지 못함 → 이전에 배포한 화면이 그대로 남습니다.
- 계속 배포하는 경우: 시트 접속 실패, 시세 수집 실패 → 이전 결과를 유지하고 경고만 남깁니다.
- 인증키는 쓰지 않습니다. 시트 주소는 공개돼도 되는 값이라 Variables에 둡니다.

## 디자인 원칙

2026-10-01 “번잡하고 어떤 사이트인지 모르겠다”는 평가로 픽셀 오락실 → **모던 핀테크** 스타일로 바꿨습니다(이름 “알고리즘 오락실”은 브랜드로 유지).

- 첫 화면 순서: 한 문장 소개(의뢰소)와 숫자 3개 → 진행 방식 4단계 → 결과물 카드 6장(질문 하나 + 핵심 결과 하나) → 의뢰 현황 → 의뢰 양식 → 만든 사람·이용 안내. 게임은 `games.html`.
- 결과 페이지도 같은 틀: 종류 · 한글 이름 · 질문 · 핵심 결과 · “이런 전략 의뢰하기” 버튼 하나. 긴 설명은 “자세히”로 접는다.
- 밝은 회색 바탕(#f2f4f6) 위 흰 카드, 둥근 모서리, 얕은 그림자. 글꼴은 Pretendard.
- 시세 색은 한국 관례: 상승 빨강, 하락 파랑, 항상 ▲▼와 함께. **빨강·파랑은 시세에만** 쓰고, 버튼은 진한 남색, 강조는 보라.
- 차트마다 위에 “그래서 무슨 뜻인지” 한 줄, 선은 2~3개 이하, 주선은 굵게, 눈금은 딱 떨어지는 값, 휴대폰에서 짚으면 값.
- `prefers-reduced-motion`이면 움직임을 멈춘다. Tab 이동 위치는 보라 테두리로 항상 보이게.
- 모든 기계 페이지에 같은 머리·꼬리: 목록으로 돌아가기, 문의 섹션, “투자 조언이 아닙니다”.

## 새 결과 페이지 추가하는 법

1. `machines/clock-tower.html`을 복사해 `machines/새이름.html`로 만든다(머리·문의·꼬리 구조 유지).
2. 계산이 있으면 `새이름/config.json`에 기준을 결과 계산 **전에** 고정하고, `build.py`와 `test_build.py`를 만든다.
3. `index.html`의 결과물 카드 목록(`#works .mc-list`)에 카드 한 장(종류·질문·핵심 결과)을 더한다. 결과 페이지 머리(`.mh-*`)에도 같은 내용을 쓰고, 의뢰받은 것이면 `requests/requests.csv` 상태를 완료로.
4. `.github/workflows/site.yml`의 test·build에 새 폴더를 더한다.
