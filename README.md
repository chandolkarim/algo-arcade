기술개발연구프로젝트(2026-2) 개인 홈페이지 과제입니다.

## 1. 목적

직접 만든 매매 알고리즘과, 시장 속설을 데이터로 따져 보는 검증기를 오락기 한 대씩 들여놓고, 교수님·수업 동료·자동매매에 관심 있는 사람에게 **각 기계가 어떻게 판단하고 기록으로 보면 실제로 어땠는지** 보여 줍니다. 틀린 결과도 지우지 않습니다. 방문자는 구경·데모 재생·차트 게임만 할 수 있고, 실제 기계는 주인만 돌립니다. 모든 기록은 모의투자·과거 데이터 결과이며 투자 조언이 아닙니다.

**7대를 돌려 본 결론**: 방향을 미리 맞히는 규칙은 거의 찾지 못했습니다(4번 효과 없음, 7번 방향 0~1칸, 6번 검증됨 2개). 대신 언제 크게 움직이는지(7번), 어떻게 하면 덜 잃는지(2번 200일선 필터)는 보였습니다.

### 1번 TRADING FLOOR
AI 에이전트 13명이 분석·토론·심사해 판정을 내는 기계입니다. 실제 기계는 로컬에서만 돌고, 코드와 프롬프트는 공개하지 않습니다. 결과: 공개 판정 24건 중 24시간 뒤 대조한 코인 19건은 맞음 2 · 빗나감 12 · 움직임 작음 5(마지막 판정 2026-09-01).

- **브라우저 데모** (`assets/floor-demo.js`): 원본 `server/demo.js`의 지표·대사·순서를 옮겼습니다. AI를 부르지 않고 코인 실시간 시세로 5단계를 연출 재생합니다. 판정에 의미가 없습니다. 매수·매도·관망 방향에 맞춰 손절·목표 위치를 바꿉니다.
- **플레이 기록** (`records/`): 기계가 낸 실제 판정을 적은 목록입니다. 코인 기록은 판정 24시간 뒤 바이낸스 현물 가격으로 등락을 계산해 원본 `report.js`의 `judge()`와 같은 규칙(±1% 미만은 “움직임 작음”)으로 판정합니다.

```bash
python3 records/build.py                       # 시트 또는 records/records.csv → data/records.json
python3 records/build.py --previous <배포된 records.json 주소>   # 시트 접속 실패 시 배포된 기록 유지
python3 -m unittest discover -s records -p 'test_*.py' -v
```

#### 플레이 기록 시트 연결 (5주차 방식)

| 열 | 필수 | 내용 |
|---|---|---|
| 일시 | 필수 | `2026-08-24 22:06` (한국 시각) |
| 모드 | 필수 | 알고리즘 / 스캘핑 / 공격 |
| 종목 | 필수 | BTC, SOL, 삼성전자 … |
| 판정 | 필수 | 알고리즘: 매수·매도·관망 / 스캘핑: 롱·숏·패스 / 공격: 롱·숏 |
| 확신도 | 필수 | 0~100 정수 |
| 판정가 | 필수 | 0보다 큰 숫자 |
| 통화 | 필수 | USD / KRW |
| 메모 | 선택 | 한 줄 |
| 공개 | 필수 | Y인 행만 웹에 표시 |

1. 새 스프레드시트 → 파일 → 가져오기 → `records/records.csv`
2. 파일 → 공유 → 웹에 게시 → 시트1 · 쉼표로 구분된 값(.csv) → 게시 (주소가 `output=csv`로 끝나야 함)
3. 저장소 Settings → Secrets and variables → Actions → **Variables** → `SHEET_CSV_URL` = 게시 주소
4. Actions → Site → Run workflow (예약 실행은 몇 시간씩 밀릴 수 있음)
5. 잘못된 행이 있으면 build가 행 번호와 이유를 출력하고 멈춥니다. 이전 화면이 그대로 남습니다.
6. 시트에 잠깐 접속하지 못한 것은 데이터 잘못이 아니므로 멈추지 않고, 이미 배포된 기록을 그대로 다시 씁니다.

시트에는 공개해도 되는 기록만 적습니다. 연락처·계좌 정보는 넣지 않습니다.

### 2번 REBOUND 25/200
BNF의 25일선 괴리율 매매에서 착안했습니다. 정찬민이 제안한 200일선 방향 필터에 ATR 진입·손절과 보유 기간을 더한 독립적인 연구 전략입니다. BNF 본인의 매매 재현이나 성과 인증이 아닙니다.

- 실제 가격으로 계산한 과거 백테스트(2022~), 최근 구간(2025~) 별도 검증, 등록 이후 모의 장부를 구분합니다.
- BTC·ETH 무기한 선물, AAPL·SPY·삼성전자·SK하이닉스. 각 종목은 독립 모의계좌입니다.
- 결과(2026-10-01): 200일선 필터를 넣으면 빼는 것보다 손실이 크게 줄었지만(필터 없음 −6~−12%), 남는 수익은 대부분 ±3% 안쪽입니다.
- Actions가 하루 한 번 다시 계산합니다. 바이낸스 선물 주소는 미국 IP(Actions 서버)에서 막힐 수 있어, 그때 코인은 마지막으로 로컬에서 계산한 결과를 유지하고 화면에 그 사실을 표시합니다.

```bash
python3 rebound/update.py
python3 -m unittest discover -s rebound -p 'test_*.py' -v
```

규칙, 데이터 출처, 비용 가정은 `rebound/README.md`. `rebound/paper/`는 등록 이후 장부이므로 보존합니다.

### 7번 CLOCK TOWER
비트코인이 한국 시간 몇 시, 무슨 요일에 많이 움직이는지 바이낸스 1시간봉(2017-08 ~, 약 8만 개)을 요일 7 × 시각 24 = 168칸으로 나눠 셉니다. 기준(`clock/config.json`)은 결과 계산 전에 고정했습니다.

- 칸마다 출렁임(|등락| 평균), 평균 등락, 오른 비율을 “평소”(같은 구간 전체 평균)와 비교하고, 2023년 전·후 두 구간 모두 같은 쪽이면 “검증됨”.
- 2026-10-01 계산: 출렁임은 168칸 중 44칸 검증됨(평일 23시 = 미국장 개장 무렵이 평소의 약 1.5~1.6배, 주말 낮이 가장 조용). 평균 등락 0칸, 오른 비율 1칸 — 언제 움직이는지는 뚜렷하지만 방향은 시간으로 알 수 없음.
- 공개 파일에는 168칸 요약만 담습니다. Actions에서는 하루 한 번만 다시 계산합니다. 페이지를 열어 둔 채 정시가 지나면 “지금” 칸이 1분 안에 옮겨 갑니다.

```bash
python3 clock/build.py
python3 -m unittest discover -s clock -p 'test_*.py' -v
```

## 자동화

`.github/workflows/site.yml` — Pages Source는 **GitHub Actions**입니다.

| 작업 | 하는 일 |
|---|---|
| test | 7개 폴더의 파이썬 테스트(98개), 화면 스크립트 문법 검사. 실패하면 배포하지 않음 |
| build | 플레이 기록(시트 검사), 김프 기록 1건 추가, 6번 상황 통계, 7번 시간대 지도·2·5번 백테스트(하루 한 번), 공개 파일만 `_site`로 모음 |
| deploy | GitHub Pages에 게시 |

| 실행 조건 | 언제 |
|---|---|
| push | main에 Push할 때 |
| schedule | `cron: "7 * * * *"` — 매시 7분 예약. 실제로는 몇 시간씩 밀리거나 빠짐(첫날 18시간에 3번) |
| workflow_dispatch | Actions 화면의 Run workflow (시트를 고친 뒤) |

- 배포하지 않는 경우: 테스트 실패, 시트 데이터 잘못, 배포된 김프 기록을 읽지 못함 → 이전에 배포한 화면이 그대로 남습니다.
- 계속 배포하는 경우: 시트 접속 실패, 시세 수집 실패 → 이전 결과를 유지하고 경고만 남깁니다.
- 인증키는 쓰지 않습니다. 시트 주소는 공개돼도 되는 값이라 Variables에 둡니다.

## 디자인 원칙

- 4px 픽셀 단위로 테두리·그림자·간격을 맞춘다.
- 시세 색은 한국 관례를 따른다: 상승 빨강, 하락 파랑. 색만으로 구분하지 않도록 ▲▼ 기호를 함께 쓴다.
- 빨강·파랑은 시세에만 쓴다. 판정·강조 표시는 노랑·민트·연보라를 쓴다.
- 픽셀 글꼴은 제목·버튼·라벨에만, 긴 문장은 시스템 글꼴로.
- `prefers-reduced-motion`을 켠 사용자에게는 움직임을 멈춘다.
- Tab 이동 위치가 항상 보이게: 어두운 바탕은 노란 테두리, 밝은 판넬은 진한 테두리.
- 모든 기계 페이지에 같은 머리·꼬리: 돌아가기, 문의 섹션, “투자 조언이 아닙니다”.

## 새 기계 추가하는 법

1. `machines/clock-tower.html`을 복사해 `machines/새이름.html`로 만든다(머리·문의·꼬리 구조 유지).
2. 계산이 있으면 `새이름/config.json`에 기준을 결과 계산 **전에** 고정하고, `build.py`와 `test_build.py`를 만든다.
3. `index.html`의 빈자리 `<div class="cabinet is-empty">`를 `<a class="cabinet" href="machines/새이름.html">`로 바꾸고 상태·종류를 고친다. “결과 한눈에”에 한 줄을 더한다.
4. `.github/workflows/site.yml`의 test·build에 새 폴더를 더한다.
