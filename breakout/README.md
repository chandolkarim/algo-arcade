# 5번 기계 · BREAKOUT 20

어제까지의 20일 가격 범위를 종가로 돌파하면 다음 시가에 진입하고, 고정한 ATR 거리로 종가를 따라 손절선을 움직이는 연구입니다. AI 호출·주문 API는 없습니다. 코인·주식 6종목의 백테스트, 최근 구간 검증, 등록 이후 모의 장부를 제공합니다.

## 실행

저장소 루트, Python 3.9 이상, 외부 패키지 없음.

```bash
python3 breakout/update.py
python3 breakout/update.py --offline
python3 -m unittest discover -s breakout -p 'test_*.py' -v
```

온라인 갱신은 공개 시세를 수집하고 결과와 모의 장부를 갱신합니다. `--offline`은 저장된 원본으로 백테스트만 재계산하고 모의 장부를 시작·진행시키지 않습니다. 현재 예약 실행과 공개 배포는 활성화하지 않았습니다.

- `engine.py`: 5번 독립 매매·계좌 엔진.
- `update.py`: 5번 수집·결과·모의 장부. 2번 `rebound.update`의 공개 시세 수집 함수를 import해서 재사용합니다. 2번의 main이나 모의 장부는 실행하지 않습니다.
- `config.json`: 예시 종목과 기간·수수료 가정.
- `cache/`: 공개 시세 원본 캐시. Git 제외.
- `paper/`: 등록 시각, 확정 봉 관측, 계좌·거래 기록. 보존 필요.
- `../data/breakout.json`: 전체 결과, 원본 데이터 해시, 수집 시각·출처.
- `../data/breakout-data.js`: 같은 결과의 file:// 호환 표시용 스크립트.
- `../machines/breakout.html`: 관측·기록·규칙·출처 페이지.

## 신호와 체결

신호일을 t라 할 때 `upper[t]=max(high[t-20:t])`, `lower[t]=min(low[t-20:t])`. 슬라이스는 t를 제외합니다. 현재 봉의 고가/저가가 기준선에 들어가지 않습니다.

- `close[t] > upper[t]`: 롱 후보. `close[t] < lower[t]`: 숏 후보. 동일하면 대기.
- 다음 봉 시가가 신호일 기준선 바깥에 남아 있어야 진입. 범위 안으로 복귀하거나 선과 같아지면 취소.
- 시가에 불리한 슬리피지를 적용한 값이 진입가. 최초 손절은 진입가 ± 신호일 Wilder ATR14의 2배.
- 롱: `stop_next = max(stop_current, best_close_since_entry - 2*signal_ATR)`.
- 숏: `stop_next = min(stop_current, best_close_since_entry + 2*signal_ATR)`.
- best_close의 초기값은 진입가. 종가가 진입가에 불리하게 움직여도 최초 손절보다 넓어지지 않습니다.
- 현재 봉은 이미 정해진 손절선으로만 처리합니다. 손절되지 않고 봉이 끝났을 때 종가로 다음 봉 손절선을 계산합니다. 당일 고가·저가를 추적 기준으로 삼지 않습니다.
- 장중 손절은 저가/고가로 판단하며 손절가에 불리한 슬리피지를 적용. 갭으로 손절가를 넘으면 시가에 불리한 슬리피지를 적용.
- 익절가·최대 보유 기간 없음. 종목당 한 포지션. 추가 진입·물타기 없음. 청산 당일 재진입 없음.
- 보유 봉 수는 진입일과 청산일을 포함합니다. 갭 청산일도 포함합니다.

## 비용·계좌

종목별 독립 모의계좌로 USD/USDT 10,000 또는 KRW 1,000만에서 시작합니다. 합산 포트폴리오가 아닙니다. 거래당 계획 손실 0.5%, 진입 시 명목금액은 자산의 100% 이내로 제한합니다. 수량 산정에는 수수료와 손절 슬리피지를 포함합니다. 갭·보유 비용은 계획 손실을 초과할 수 있습니다.

수수료는 편도 코인 0.05%, 주식 0.10%, 슬리피지 편도 0.05% 가정입니다. 주식 숏은 차입 가능 가정, 연 5% 추정 차입료를 달력 경과 일수로 반영합니다. 배당은 전일 보유 포지션에 롱 수취·숏 지급합니다. 소수 수량 허용, 세금·실제 차입 제한·리콜·최소 주문 단위·증거금·강제 청산 규칙은 미반영입니다.

선물 펀딩은 실제 이력을 사용합니다. 과거 mark 가격 누락 시 일봉 시가를 대용합니다. UTC 00시 부근 펀딩은 시가 직전 보유분에만 반영하며 신규 시가 진입분에는 부과하지 않습니다. 손절일은 손절 시각을 일봉으로 알 수 없으므로 이후 펀딩 지출을 전부 반영하고 수취를 제외하는 보수적 근사입니다. 이는 정확한 체결별 펀딩 재현이 아닙니다.

## 데이터·검증 해석

BTCUSDT·ETHUSDT 선물, AAPL·SPY·삼성전자·SK하이닉스를 예시로 사용합니다. 고정된 소수 생존 종목의 선정 편향이 있습니다. 코인은 종료된 UTC 일봉, 주식은 현지 날짜보다 앞선 일봉을 사용하므로 주식은 당일 장 마감 후에도 다음 현지 날짜까지 기다립니다.

Yahoo의 한국 주식 누락/불가능한 OHLC는 NAVER 실제 일봉으로 보완합니다. 인접 최소 2일 종가가 두 제공자에서 1% 이내인지 확인하고 원본과 화면에 보완 출처·날짜를 표시합니다. 제공자 자체 데이터의 독립 원장 검증을 수행한 것은 아닙니다.

2022년부터 전체, 2025년부터 별도 초기 계좌로 최근 구간을 계산합니다. 수치 최적화를 수행하지 않았으며 최근 구간도 과거 데이터입니다. 완전히 새로운 미래 검증은 모의 장부에 따로 기록합니다.

계좌 수익률은 미청산 평가손익을 포함하고 미래 청산 비용은 제외합니다. 최대 낙폭은 일봉 종가 계좌 기준입니다. 승률·평균 이익·평균 손실·방향별 확정 손익·평균 보유 봉은 청산 거래만 사용합니다. 표본이 없으면 null/표본 없음입니다. 승률과 평균 손익을 함께 봐야 합니다.

## 모의 장부와 실패 처리

첫 온라인 수집 시 등록 시각과 마지막 확정 봉을 저장합니다. 등록 다음 현지 날짜부터 신규 진입이 가능하며, 등록 전에 이미 지나간 시가로 소급 진입하지 않습니다. 갱신 때 새 확정 봉을 순서대로 처리하고 실제 관측 시각을 보존합니다. 이는 일봉 기반 모의 체결이며 실시간 주문 기록이 아닙니다.

동일 봉 중복 처리 금지. 규칙 변경이나 마지막 관측 봉/지표 정정은 오류로 표시하고 기존 모의 장부를 보존합니다. 기업 분할 등으로 과거 데이터가 바뀌면 검토·재기준화가 필요합니다. 단순히 장부를 삭제해 성과를 다시 시작하면 안 됩니다.

수집 실패 시 해당 종목의 마지막 정상 결과가 있다면 stale로 표시하고 유지합니다. 정상 결과가 없으면 오류만 표시합니다. 하나라도 실패하면 갱신 명령은 종료 코드 1을 반환합니다. GitHub Actions가 `--previous <배포된 결과 주소>`로 하루 한 번 다시 계산합니다(2026-10-01부터). 그날 이미 계산했으면 배포된 결과를 그대로 씁니다. Actions는 장부를 저장소에 커밋하지 않으므로, 매번 저장소에 커밋된 `breakout/paper/` 장부(등록 시점의 기준 봉)에서 시작해 그 뒤의 확정 봉을 처음부터 다시 처리합니다. 같은 입력이면 결과가 같아 장부가 이어집니다. 동시 실행은 워크플로의 `concurrency`로 막습니다. 수집에 실패한 종목은 배포된 이전 결과를 stale로 유지합니다(바이낸스 선물 주소는 미국 IP에서 막힐 수 있음). 로컬에서 `update.py`를 실행하면 `breakout/paper/`가 앞으로 당겨지니 커밋해 둡니다.
